## Le seul vrai gain : les images

Les 24 portraits de mobs pèsent **792 Ko** et font **384 px de large**. Affichage
réel : boss ~105 px, pack ~74 px, midboss ~55 px. Même en 2×, **210 px suffiraient**.
`map.webp` fait 1 300 px pour un affichage à 533 px.

- **Redimensionner à 224 px** → gain attendu **350 à 450 Ko** sur le guide, aucun
  code touché. C'est l'action à faire.
- `srcset`/`sizes` ne se justifie que pour la carte de fond (533 px → plein écran
  en lightbox). Les mobs s'affichent tous dans une fourchette étroite : une seule
  taille bien choisie fait le travail.

Déjà bon : WebP partout, `loading="lazy"` sur les portraits, polices variables
auto-hébergées (104 Ko pour trois familles).

## Dette réelle

1. **Écriture de `data.js` dupliquée** — Map Studio et Strat Studio ont chacun leur
   copie de `idbReq`/`idbGet`/`idbSet`/`toast`, de la demande de permission et de la
   regex de remplacement de blocs. C'est la duplication la plus dangereuse du projet :
   si la forme d'un bloc change d'un côté, un outil corrompt ce que l'autre écrit.
   → extraire dans `js/data-file.js`, y brancher le test d'aller-retour existant.
2. **CSS mort** — 7 règles `.ovlegend` et `.phasemap` dans `css/style.css` décrivent
   ce qu'`app.js` ne produit plus.
3. **`tools/map-editor.html`** — 494 lignes, remplacé par Map Studio, encore câblé
   sur le socle donc à maintenir d'accord à chaque évolution du modèle. À supprimer.

Note : les 23 `catch` vides sont tous des gardes autour de `localStorage` — légitimes
en navigation privée. 0 `TODO`, 0 `console.log`.

## Recherches — retenu / écarté

- **`srcset`/`sizes`** → retenu en version simple (voir ci-dessus).
- **Optimisations Konva** — les recommandations officielles sont : calques séparés,
  `listening(false)` sur ce qui n'écoute pas, `batchDraw`. Map Studio fait déjà les
  trois. Restent `perfectDrawEnabled:false` sur les formes fond+contour et `cache()`
  sur le calque de carte — **seulement si une lenteur se fait sentir**, ce qui n'est
  pas le cas.
- **`content-visibility:auto`** → à essayer sur `.phase` dans le guide (952 nœuds,
  longue page à défilement), avec `contain-intrinsic-size` pour éviter le saut de
  scrollbar. Supporté par les trois moteurs depuis Safari 18 / Firefox 125.
  **À mesurer avant/après et à garder seulement si l'écart est réel.**
- **Sass / Tailwind / un build** → **non, et c'est un choix.** Nested rules, container
  queries, `:has()`, `color-mix()` et cascade layers sont natifs ; le projet utilise
  déjà les quatre premiers. Un build casserait la propriété la plus précieuse du site :
  on ouvre un fichier, on le modifie, GitHub Pages le sert. Si la feuille devenait
  dure à tenir, la réponse serait `@layer`, pas un compilateur.
