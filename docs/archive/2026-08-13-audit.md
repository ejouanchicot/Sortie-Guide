la lightbox plein écran sur un 5K physique — assez rare pour ne pas justifier un

### 2 · Écriture de `data.js` extraite — `65716e9`

Nouveau `js/data-file.js`, partagé par les deux outils. Voir `_CLAUDE-CONTEXT.md`.

Découverte au passage : **les deux regexes n'étaient pas les mêmes**. Map Studio
cherchait `const NOM=[…];` en non-gourmand, donc s'arrêtait au premier `];`
rencontré ; Strat Studio exigeait le crochet fermant en début de ligne. La forme
unifiée est la seconde, la seule sûre — les sérialiseurs indentent tous les crochets
imbriqués.

La poignée de fichier est maintenant partagée (base IndexedDB `sortie-outils`) : on
choisit `data.js` **une fois pour les deux outils**. Effet de bord : les poignées des
anciennes bases `mapstudio` / `stratstudio` sont orphelines, il faut re-sélectionner
`data.js` une seule fois.

Couverture : 17 contrôles sur le module (aller-retour des 19 blocs des deux outils
réunis, idempotence, contenu écrit à la main intact, bloc absent signalé et jamais
inséré, `$&` du contenu non interprété, `];` imbriqué qui ne tronque pas) et 19
contrôles de bout en bout dans le navigateur, en cliquant vraiment sur *Enregistrer*
avec une fausse API fichier.

À savoir : Strat Studio réécrit les chaînes en apostrophes simples là où `data.js`
utilise des guillemets. Le contenu est identique (vérifié), mais le `git diff` est
plus bruyant qu'il n'y paraît. Comportement d'origine du sérialiseur, pas une
régression.

## Recherches — retenu / écarté

- **`srcset`/`sizes`** → retenu en version simple : une seule taille suffit pour les
  portraits, qui s'affichent tous dans une fourchette étroite.
- **Optimisations Konva** — les recommandations officielles sont : calques séparés,
  `listening(false)` sur ce qui n'écoute pas, `batchDraw`. Map Studio fait déjà les
  trois. Restent `perfectDrawEnabled:false` sur les formes fond+contour et `cache()`
  sur le calque de carte — **seulement si une lenteur se fait sentir**, ce qui n'est
  pas le cas.
- **`content-visibility:auto`** → fait, voir plus haut.
- **Sass / Tailwind / un build** → **non, et c'est un choix.** Nested rules, container
  queries, `:has()`, `color-mix()` et cascade layers sont natifs ; le projet utilise
  déjà les quatre premiers. Un build casserait la propriété la plus précieuse du site :
  on ouvre un fichier, on le modifie, GitHub Pages le sert. Si la feuille devenait
  dure à tenir, la réponse serait `@layer`, pas un compilateur.
